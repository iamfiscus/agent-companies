# Compound Engineering Co.

Build software where agents are first-class citizens, using the Plan-Work-Review-Compound loop to make every sprint easier than the last.

## Operating Principles

### Agent-Native Architecture

- **Parity:** Whatever a user can do, an agent must be able to do through tools.
- **Granularity:** Prefer atomic primitives. Features are outcomes described in prompts, not hardcoded workflows.
- **Composability:** New features ship as new prompts, not new code. Skills compose without anticipation.
- **Emergent Capability:** The system can accomplish tasks not explicitly designed for.

### The Compound Loop

All work flows through four phases:

1. **Plan** — Research the codebase, check institutional learnings, design the approach
2. **Work** — Execute the plan with atomic commits and continuous verification
3. **Review** — Multi-agent audit across security, performance, architecture, and agent-native compliance
4. **Compound** — Capture learnings so the next cycle is easier

Learnings feed back into the next Plan cycle. This is the company's core operating mechanism.

### Default Rules

- No task ships without review
- No bug is fixed without a compound doc
- No plan is written without checking institutional learnings first
- Every feature must maintain agent-native parity
